# 岩手県山田町の観光・くらしRAG

観光施設と家庭ごみの質問を、同じ検索窓口で扱う学習用の試作です。公式資料5件を、個別に検索できる10件の短い要約にまとめています。各要約には出典URLと確認日があります。

今後のモデル、検索、聞き返しの構成は [Agentic RAGの設計案](docs/agentic-rag-design.md) にまとめています。設計の根拠と評価例は [設計調査ノート](docs/agentic-rag-research.md) に記録します。

## ブラウザーで使う

手元に保存した `yamada-guide.html` をブラウザーで開きます。サーバーの起動は不要です。質問を入力するか、観光・くらしの質問例を選ぶと、資料の要約と出典リンクが表示されます。「AIに渡す内容をコピー」で、質問と根拠をまとめてチャットに渡せます。資料を更新した後は `python3 -B export_html.py` でHTMLを作り直せます。

Gemma 4 12Bで自動回答を使う場合は、下の手順3でOllamaを用意します。その後、ブラウザーと同じ端末で `python3 -B yamada_web.py --model` を実行し、[http://127.0.0.1:8765](http://127.0.0.1:8765/) を開きます。AIとの接続に失敗した場合は、同じ画面に資料検索の結果を表示します。停止するときはターミナルで `Ctrl+C` を押します。

## 1. まず資料を検索する

ターミナルでこのフォルダを開き、次のコマンドを1行ずつ実行します。Python 3の標準ライブラリだけで動きます。

```bash
python3 yamada_rag.py '鯨と海の科学館と道の駅やまだは、通常どちらが遅く閉まりますか？'
python3 yamada_rag.py 'ペットボトルのふたとラベルはどう出しますか？'
python3 yamada_rag.py '明日の混雑状況は？'
```

最初の質問では両施設の開館時間、2問目では町の分別資料が表示されます。3問目では確認できる根拠がない旨を表示します。出典を開いて、検索結果の内容と見比べてみてください。

## 2. 検索結果から回答を作る

`--prompt` を付けると、検索結果と、資料に基づいて出典付きで回答するための指示が一緒に表示されます。その出力をチャットに貼って試せます。

```bash
python3 yamada_rag.py --prompt '鯨と海の科学館と道の駅やまだは、通常どちらが遅く閉まりますか？'
```

この例では、科学館の通常の閉館は17:00、道の駅は18:00なので、道の駅のほうが1時間遅く閉まると答えられます。両施設のURLが回答に付いているかも確認します。

## 3. AIに追加検索を任せる

対応版のOllamaを起動します。Linuxでまだ起動していない場合は、別のターミナルで `ollama serve` を実行します。モデルの取得は初回だけで、ダウンロードは約8 GBです。この試作はOllama 0.40.16で動作を確認しています。 [Ollamaのダウンロード](https://ollama.com/download) · [Gemma 4 12B](https://ollama.com/library/gemma4:12b)

```bash
ollama pull gemma4:12b
python3 yamada_rag.py --model --trace '岩手船越駅が最寄りの施設とおいすたは、通常どちらが遅く閉まりますか？'
python3 yamada_rag.py --model --trace --baseline '岩手船越駅が最寄りの施設とおいすたは、通常どちらが遅く閉まりますか？'
```

`--model` を付けるとローカルのGemma 4 12Bで回答します。`--model gemma4:12b` と明示することもできます。この質問の初回検索では、科学館へのアクセスと道の駅の開館時間が見つかります。AIが科学館の開館時間を追加で検索するかを `--trace` で確認できます。`--baseline` を付けると初回の検索結果だけで答えるため、追加検索の効果を見比べられます。

## 4. 回答と出典をまとめて評価する

Ollamaを起動した状態で、次のコマンドをこのフォルダから実行します。既定のGemma 4 12Bで、観光・くらしの同じ10問を初回検索のみと追加検索ありの両方で試します。全件の実行には数分かかることがあります。

```bash
python3 -B evaluate_rag.py --output evaluation-results.json
```

結果JSONには、期待する答えと公式URL、実際の回答と出典、検索語と見つかった資料ID、応答時間が入ります。応答時間は各質問の検索から回答までを測り、最初のモデル読み込みは除きます。比較問題だけ試すには `--case compare-by-station` を追加します。

質問と判定条件は [`evaluation/questions.json`](evaluation/questions.json) にあります。自動判定では、回答に必要な語句や数値が含まれ、必要な資料IDとURLが出典に含まれるかを確認します。文全体で意味が合っているかは、実際の回答も読みます。コマンドの終了コードは全件合格が `0`、要確認の回答がある場合が `1`、接続などの実行エラーが `2` です。初回検索のみでは答えられず、追加検索ありで合格するケースも結果に残します。

## 資料を増やすとき

`sources.json` の各資料には、観光・くらしの区分、公式URL、確認日があります。検索する単位ごとに `records` の中に要約を置き、重複しない `id`、施設名や品目を探す `keywords`、開館時間や分別など質問の内容を見分ける `topics` を付けます。

試作が参照するのは登録した要約です。各施設の臨時変更や日付指定の営業状況は、公式サイトで確認してください。ごみの具体的な収集日は、町のページから該当地区の日程表を開いて確認できます。 [山田町の地区別ごみ収集日程表](https://www.town.yamada.iwate.jp/docs/8354.html)
