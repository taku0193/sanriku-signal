# 岩手県山田町の観光・くらしRAG

岩手県山田町の観光、交通、くらしを出典付きで案内する学習用の試作です。基本資料には町や施設、地域団体・事業者の公開情報の要約を収録しています。町と観光協会の記事を取り込むと、手続き、子育て、防災、歴史、名所、宿泊、特産品なども検索できます。

検索、聞き返し、回答の構成は [ReActの設計](docs/agentic-rag-design.md) に、根拠と評価例は [設計調査ノート](docs/agentic-rag-research.md) にまとめています。

## サーバーで資料検索を試す

Gitと、Node.js（`^20.19.0 || >=22.12.0`）およびnpmを用意します。基本資料はリポジトリの `sources.json` と `knowledge/` に同梱されています。

リポジトリをクローンし、ルートに移動して以下を順に実行します。

```bash
git clone https://github.com/taku0193/sanriku-signal.git
cd sanriku-signal
npm ci
npm run build
npm start
```

**初回は `npm start` の前に `npm run build` を実行してください。** ビルドで起動に必要な `.runtime/typescript/server/main.js` が生成されます。ビルド前に起動すると `MODULE_NOT_FOUND` が出ます。

1. ブラウザーで [http://127.0.0.1:8765/](http://127.0.0.1:8765/) を開き、ニックネームを入力して「案内へ進む」を押します。
2. 「資料検索モード」と表示された画面で、質問例の「科学館の入館料」を選びます。
3. 「出典」欄に一般料金が大人300円と書かれた資料と、鯨と海の科学館「施設情報」へのリンクが表示されることを確認します。

「かがくかんのにゅうかんりょう」や「かがっかんの入館料」でも、同じ資料を検索できます。

ニックネームは画面表示用としてブラウザーのタブ内に保存されます。「案内の入口へ戻る」から変更できます。停止するには、サーバーを起動したターミナルで `Ctrl+C` を押します。

### 8765番ポートが使用中の場合

起動時に `EADDRINUSE` が出たら、空いているポートを指定して起動し直します。8766番を使う場合は次のコマンドを実行し、ターミナルに表示されたURL（この例では [http://127.0.0.1:8766/](http://127.0.0.1:8766/)）を開きます。

```bash
npm start -- --port 8766
```

## AI回答を試す

Ollamaをインストールして起動します。Linuxでまだ起動していない場合は、別のターミナルで `ollama serve` を実行します。この試作はOllama 0.40.16で動作を確認しています。 [Ollamaのダウンロード](https://ollama.com/download) · [Gemma 4 12B](https://ollama.com/library/gemma4:12b)

リポジトリのルートでモデルを取得し、一覧に `gemma4:12b` が表示されることを確認します。初回のダウンロードは約8 GBです。

```bash
ollama pull gemma4:12b
ollama list
```

資料検索サーバーを起動中なら `Ctrl+C` で停止し、ビルド済みのサーバーをAI回答付きで起動します。別ポートを使う場合は `npm start -- --model --port 8766` のように指定します。

```bash
npm start -- --model
```

ターミナルに表示されたURLを開き、チャット画面で「科学館の入館料」を選びます。回答本文に大人300円と表示され、回答の下の「出典」を開くと鯨と海の科学館「施設情報」へのリンクを確認できます。

画面の「AI回答モード」は、サーバーに回答モデルが設定されていることを示します。AIの応答を読み取れない場合は、同じ資料と質問で一度だけ作り直します。接続できない場合などは、理由を表示して資料検索に切り替えます。「科学館の大人の入館料は？」では、該当する資料の大人300円の記載も本文に表示します。質問に対応する記載が確認できない場合は、その旨を伝えます。「AI回答を再試行」で、聞き返しへの返答を含めて最後の質問をもう一度送れます。

サーバーは既定で `http://127.0.0.1:11434/api/chat` に接続します。Ollamaを別ポートで起動した場合は、`YAMADA_CHAT_URL` に `http://127.0.0.1:11435/api/chat` のように接続先を指定します。

AI回答モードでは検索や確認の進み具合が会話欄に表示されます。通常は検索先を選ぶ、取得資料を照合する、回答するの3段階です。不足があれば追加検索します。1入力につき検索は最大5回、検索や回答を選ぶ行動判断は最大6回、取得資料の照合は1回です。「鯨と海の科学館の入館料は？」に続けて「そこは何時まで？」と質問できます。会話の文脈は開いているページ内で使い、「新しい会話」でリセットします。

資料に基づく回答は、生成された文から順に表示します。回答を停止すると、画面に途中までの文が残ります。最新の回答を追っているときは、画面に収まらない検索結果や回答を先頭から読めます。過去の回答を読んでいるときはその位置を保ち、「最新のメッセージへ」で新しい結果に移動できます。

「うちの地区の次の燃やせるごみの日は？」と質問し、地区名を聞かれたら「大沢です」と入力します。回答に、収集予定の日付と曜日が表示されます。「大沢の2026年12月のプラスチック収集日」のように期間と種類を指定することもできます。

## 単体HTMLで資料検索を試す

手元に保存した `yamada-guide.html` をブラウザーで直接開きます。ニックネームを入力して「案内へ進む」を押し、質問を入力するか質問例を選ぶと、同梱の基本資料の要約と出典リンクが表示されます。「質問と資料をコピー」で、質問と根拠をまとめてチャットに渡せます。

写真が登録されている施設は、サーバー版と単体HTMLの両方で現地の写真が表示されます。写真と資料IDの対応、撮影者、利用条件は [写真目録](photo_catalog.json) で管理します。

### 単体HTMLをPythonで再生成する

資料や画面を更新した後は、Python 3が使える環境でWeb版をビルドし、画面のビルドと基本資料を単体HTMLに埋め込みます。依存パッケージは上の手順でインストールしておきます。

```bash
npm run build
python3 -B export_html.py
```

## Web版を開発する

`frontend/` にReactの画面、`server/` に検索・ReAct・HTTP API、`shared/` にブラウザーとサーバーの共通検索処理があります。Web版はTypeScriptで実装しています。`npm run build` は型をチェックし、画面の `web/app.js` とNode.js用のサーバーを生成します。以前の `python3 -B yamada_web.py` も、ビルド済みのNode.jsサーバーを起動します。

## 1. まず資料を検索する

ターミナルでこのフォルダを開き、次のコマンドを1行ずつ実行します。Python 3の標準ライブラリだけで動きます。

```bash
python3 yamada_rag.py '鯨と海の科学館と道の駅やまだは、通常どちらが遅く閉まりますか？'
python3 yamada_rag.py 'ペットボトルのふたとラベルはどう出しますか？'
python3 yamada_rag.py '織笠駅に駐車場はありますか？'
```

最初の質問では両施設の開館時間、2問目では町の分別資料、3問目では三陸鉄道の駅情報が表示されます。出典を開いて、検索結果の内容と見比べてみてください。

## 2. 検索結果から回答を作る

`--prompt` を付けると、検索結果と、資料に基づいて出典付きで回答するための指示が一緒に表示されます。その出力をチャットに貼って試せます。

```bash
python3 yamada_rag.py --prompt '鯨と海の科学館と道の駅やまだは、通常どちらが遅く閉まりますか？'
```

この例では、科学館の通常の閉館は17:00、道の駅は18:00なので、道の駅のほうが1時間遅く閉まると答えられます。両施設のURLが回答に付いているかも確認します。

## 3. PythonのCLIでReActを試す

OllamaとGemma 4 12Bを用意してから実行します。 [AI回答の準備手順](#ai回答を試す)

```bash
python3 yamada_rag.py --model --trace '岩手船越駅が最寄りの施設とおいすたは、通常どちらが遅く閉まりますか？'
python3 yamada_rag.py --model --trace --baseline '岩手船越駅が最寄りの施設とおいすたは、通常どちらが遅く閉まりますか？'
```

`--model` ではローカルのGemma 4 12Bが最初の行動を選びます。`--trace` を付けると、選んだ行動、検索語や地区・年度、取得した出典IDが表示されます。1回の入力につき検索は最大3回、行動判断は最大4回です。`--baseline` では、Pythonが質問文で1回検索し、その結果からAIが回答します。

## 4. 回答と出典をまとめて評価する

Ollamaと埋め込み索引を用意し、Webと同じReActを観光・くらし・子育て・交通・防災などの質問で評価します。曖昧な質問への聞き返しとその続き、最新情報と通常案内を同時に尋ねる質問、対象外の質問も含みます。標準評価では検索方式ごとの上位3件も照合します。

```bash
npm run evaluate:server -- --output /tmp/sanriku-evaluation.json
npm run evaluate:server -- --suite field --output /tmp/sanriku-field.json
```

結果JSONには、ターンごとの回答・出典、Gemmaが選んだ検索先と検索方式、取得した資料ID、応答時間が入ります。駅から施設を特定する例だけ試すには `--case compare-by-station` を追加します。必要な語句・出典・行動の判定条件は [評価質問](evaluation/questions.json) にあります。検索上限、聞き返しの引き継ぎ、HTTPでのストリーミングは、Ollamaなしで `npm run test:server` を実行して確認できます。

`field` は文化・地域行事、交通、住民手続きを各10問ずつ含む評価です。まず質問と期待する事実・出典を記録し、修正前の回答を保存します。検索ログの資料IDを確認すると、出典の収録、検索順位、回答に使った根拠のどこを直すべきか分かります。 [現地の質問を想定した30問](evaluation/field-questions.json)

初回検索のみ・旧版の追加検索・Python版のReActを比較するには `python3 -B evaluate_rag.py` を使います。Python版のReActを実行するときは `--mode react` を指定します。

## 言い換えに対応する検索を試す

一般資料のキーワード検索に、EmbeddingGemmaによる意味の近さを使った検索を組み合わせられます。ローカルOllamaを起動し、このフォルダで以下を実行します。索引の初回作成にかかる時間は資料数と実行環境によります。 [Ollamaの埋め込みAPI](https://docs.ollama.com/api/embed) · [EmbeddingGemma 2](https://ollama.com/library/embeddinggemma-2:270m)

```bash
ollama pull embeddinggemma-2:270m
python3 -B -m yamada_embeddings
npm start -- --model --retrieval hybrid
```

起動時の既定値はキーワード検索です。Webを `--retrieval hybrid` で起動すると、Gemmaは検索ごとに併用・キーワード・意味検索を選べます。検索結果の資料IDを指定すると、同じ出典から続きや関連する節を探せます。地区ごとの収集日は専用の日程表を照合します。

索引の `embeddings-cache.json` は資料から再生成するローカルファイルです。資料を更新したら `python3 -B -m yamada_embeddings` で差分を反映します。索引や埋め込みサーバーを利用できないときはキーワード検索に切り替わります。埋め込み用Ollamaの接続先を変える場合は `YAMADA_EMBED_URL`、モデル名を変える場合は `YAMADA_EMBED_MODEL` を設定します。設定変更後は同じ設定で索引を生成してアプリを起動します。

## 資料を増やすとき

山田町の記事一覧と、山田町観光協会の公開一覧・サイトマップから本文、見出し、出典URL、取得日を保存します。掲載日が確認できる場合は、その日付も保存します。観光協会からは名所・宿泊・体験観光・イベント・お知らせ・震災の写真説明を取得し、飲食店は地区別ガイドから店ごとに取り込みます。初回と更新時に、このフォルダで実行します。町の記事の取得には数分かかります。 [山田町の記事一覧](https://www.town.yamada.iwate.jp/docs/) · [山田町観光協会のサイトマップ](https://www.yamada-kankou.jp/wp-sitemap.xml) · [飲食店ガイド](https://www.yamada-kankou.jp/gourmet/)

```bash
python3 -B import_town_knowledge.py
python3 -B import_town_knowledge.py --source tourism
python3 -B audit_knowledge.py
python3 -B yamada_rag.py 'ふれあいセンターはぴねの休館日は？'
python3 -B yamada_rag.py '豊間根の復活おがたの定休日は？'
```

取得結果は `town_articles.json` と `tourism_articles.json` に保存されます。それぞれ本文と、取得できなかった記事のURL・理由・前回の本文を採用したかどうかが入ります。503など一時的な失敗が一部の記事で起きたときは、その記事に前回の本文を使います。一覧取得や本文の全件取得に失敗した場合は、前回のファイルで検索を続けられます。この2ファイルはローカル生成データです。更新後はWebサーバーを再起動すると、新しい資料を読み込みます。試しに少数のページを取得するときは `--limit 10 --output sample.json` のように別の保存先を指定できます。

施設名や品目と質問の項目が基本資料に一致したときは、その要約を優先します。その他の質問では、取得した記事の見出し・本文から候補を探します。HTML本文と同じサイト内の添付URLを保存します。検索できる添付の情報は、下記の日程表や、基本資料として内容を確認して登録した人口統計などです。索引を再生成した後に `python3 -B audit_knowledge.py --embeddings` を実行すると、全資料の本文と索引の対応も確認できます。

PDFから基本資料を作るときは、発行元の一覧で版や対象年度を確認し、表の列、凡例、注記を原本で照合します。適用条件を回答用の本文に含め、`#page=` 付きのURLで該当ページを示します。調査した資料と検索・回答の結果は [ナレッジの点検記録](docs/knowledge-audit.md) に記載しています。

`sources.json` に、交通事業者、地域団体、商店、漁協、地域メディアなどの確認済み情報を要約して登録します。資料ごとに分野・発信元・出典URL・確認日を置き、検索単位ごとに `id`、施設名や品目を探す `keywords`、開館時間や分別など質問の内容を見分ける `topics` を付けます。更新時は発信元のページを確認して要約と確認日を更新します。

人が書いて見直すFAQは `knowledge/` にMarkdownで保存できます。[町の花・木・鳥のFAQ](knowledge/town-symbols.md) の形式で、冒頭の `---` で囲まれた箇所に題名、分野、出典、URL、確認日、検索語と項目を置き、その後に本文を書きます。検索語と項目は半角カンマで区切ります。MarkdownとJSONは同じ資料検索で利用でき、単体HTMLには手作業で整えた資料が入ります。

文化財・地域資源の名称、読み、分類は `regional_resources.json` に保管します。公開一覧を更新するには `python3 -B import_regional_resources.py` を実行します。冊子や発行元で確認した詳しい内容は `knowledge/` に記載し、必要なら `names` に正式名・別名・読みを半角カンマ区切りで登録します。たとえば「海よ光れ」では全校劇と学校新聞の違いを説明し、書籍や番組を尋ねられたときはそれぞれの資料を参照します。 [文化財・地域資源の公開一覧](https://cuckoo.si.soft.iwate-pu.ac.jp/~yamada_prj/index.php?page=bunkazai_list)

`collection_calendars.json` に公式PDFと地区の対応、`collection_calendar_days.json` に令和8年度の区分別・品目別の日付を保存します。回答には日付と出典の文書名が表示されます。地区名が複数の収集区分にまたがる場合は、区番号やごみステーションの目印を尋ねます。相対的な日付は日本時間を基準にし、「次回」は翌日以降の予定を案内します。

日付データを照合し直すには、公式PDFを資料IDと同じ名前で保存し、`pdftotext` が使える環境で `python3 -B import_calendar_days.py --pdf-dir <PDFのフォルダ>` を実行します。各月の欄と燃やせるごみの曜日が公式表と一致した場合に、日付JSONを更新します。

ごみ収集日の回答は登録した年度の日程表に基づきます。12月29日〜31日が該当する場合は日程表の変更注意も表示します。臨時の営業変更、当日の運行やイベントの変更は各発信元が案内します。 [山田町の地区別ごみ収集日程表](https://www.town.yamada.iwate.jp/docs/8354.html)

## 年度・改正日・開催日がある資料を更新する

| 資料 | 確認するタイミングと更新先 |
| --- | --- |
| 地区別ごみ収集日程 | 4月の年度切り替えの45日前から点検します。町が新年度版を公開したら、地区名・地区の別名・PDFと日付JSONを年度ごとに追加し、年始と年度境界の回答を確認します。 [町の日程表](https://www.town.yamada.iwate.jp/docs/8354.html) |
| バスの時刻・運行ルール | 30日ごととダイヤ改正の発表時に、改正日、平日と休日、年末年始などの注記を照合します。要約、確認日、対象期間、出典のPDFを更新します。 [岩手県北バスの宮古・山田エリア](https://www.iwate-kenpokubus.co.jp/regular/map/miyako/) · [町のいぐバス案内](https://www.town.yamada.iwate.jp/docs/10434.html) |
| イベント・季節営業 | 開催年の公式発表時と、延期・中止の発表時に、日付、会場、案内本文、出典を見直します。日程が確定したら、その年の資料IDと対象期間を登録します。 [町のイベント情報](https://www.town.yamada.iwate.jp/kurashi/event/) · [山田祭り公式案内](https://yamada-matsuri.com/) |

`source-periods.json` の `from` と `through` は、資料が示す日程や制度の開始日と終了日です。終了日が未公表の時刻表は `from` を登録し、本文を確認した日から30日後を点検日とします。公式ページが同じURLで翌年分に更新される場合は、`snapshots` の掲載日と対象期間を照合します。終了したイベント資料は、当時の質問に答えるために保管します。地区別の期間は日程表の `fiscal_year` から求めます。新年度のPDFは列、曜日、注記を改めて照合してください。入稿済みの令和8年度を照合する `import_calendar_days.py` は、同年度の表に合わせた検証コードです。

更新後は必要に応じて記事を取得し直し、次を実行して索引を更新します。監査結果の `periods` に再確認が必要な資料と日程表が未収録の年度が出ます。

```bash
python3 -B -m yamada_embeddings
python3 -B audit_knowledge.py --embeddings
python3 -B audit_knowledge.py --as-of 2027-03-15
npm run evaluate:server -- --suite field --output /tmp/sanriku-field.json
```
